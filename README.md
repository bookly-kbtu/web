# Bookly Web

React + TypeScript + Vite. Каталог салонов, поиск по названию и адресу, города и категории, страницы услуг и мастеров, локальное избранное, вход и регистрация по OTP.

Оформление по референсу Bookly: коралловый бренд, розовые поверхности, светлый фон, графитовый текст. Адаптивные карточки, анимации с поддержкой reduced motion и модальные окна с управлением с клавиатуры.

```sh
npm install
npm run dev
```

По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8080`. Для другого адреса создайте `.env.local` с `API_TARGET` (пример в `.env.example`). Запустите backend и инфраструктуру по инструкциям в `../backend/README.md`.

`npm run build` проверяет TypeScript и создаёт `dist`. Для production настройте reverse proxy `/api` на backend либо задайте `VITE_API_URL` при сборке и разрешите CORS на API.

`npm run test:e2e` запускает браузерные проверки на desktop/mobile (нужен работающий dev-сервер и `npx playwright install chromium`). Тесты используют подменённые ответы API, не изменяют базу. `npm run format` форматирует исходники.

## Структура

- `src/App.tsx`: каталог, фильтры, пагинация и избранное.
- `src/Masters.tsx`: онлайн-запись к мастерам Bookly: услуга, адрес, день, свободный слот.
- `src/Account.tsx`: кабинет: профиль, мои записи, уведомления.
- `src/MasterCabinet.tsx`: кабинет мастера: профиль, адреса, услуги, рабочие часы, исключения и записи клиентов.
- `src/Admin.tsx`: администрирование: категории, пользователи и роли, мастера, записи, импорт zapis.kz.
- `src/components.tsx`: карточки, фотографии, модальные окна и детали салона.
- `src/Auth.tsx`: OTP, регистрация, профиль и выход.
- `src/api.ts`: типы API, запросы и форматирование цен.
- `src/styles.css`: адаптивный интерфейс.
- `src/MapExplore.tsx`: карта со списком салонов, геолокация, поиск по радиусу и дозагрузка результатов.
- `src/MapCanvas.tsx`: Leaflet/OpenStreetMap и 2ГИС MapGL, маркеры и управление картой.
- `src/maps.ts`: проверка координат и ссылки на 2ГИС, Яндекс и Google.

Фотографии загружаются из API, при отсутствии используется нейтральная заглушка. Демоданные не подменяют ответы сервера. Избранное хранится в браузере. OTP сейчас является заглушкой backend, используйте код из его конфигурации `OTP_STATIC_CODE`.

## Карта

Карта открывается сразу. Без ключа работает Leaflet с OpenStreetMap. Для 2ГИС добавьте в `.env.local` `VITE_2GIS_KEY=<ваш браузерный ключ Map Tiles API>` и перезапустите Vite. Ключ VITE доступен клиенту: используйте предназначенный для браузера ключ с ограничением доменов. [Получение ключа и настройка 2ГИС](https://docs.2gis.com/mapgl/start/first-steps).

Для собственного провайдера растровых тайлов предусмотрены `VITE_MAP_TILE_URL` и `VITE_MAP_ATTRIBUTION`. Стандартный OSM используется с видимой атрибуцией, без предзагрузки/офлайн-скачивания; для большого трафика выберите подходящий хостинг тайлов по [политике OSM](https://operations.osmfoundation.org/policies/tiles/).

На карте только реальные координаты из `/market/firms`. Места без координат остаются в списке. Загружается до 100 результатов за запрос, остальные доступны через «Показать ещё»; счётчик обозначает загруженную подборку, а не весь город. «Искать здесь» отправляет центр карты и `radius_m`; геолокация запрашивается только по нажатию, требует HTTPS или localhost. Ссылки 2ГИС/Яндекс/Google работают без ключа.

## Актуальный backend (24.09.2026)

- `/market/cities`, `/market/categories`, `/market/firms` и детали/фото/услуги/мастера фирмы: публичный импортированный каталог. Геопоиск: `lat`, `lng`, `radius_m`, расстояние в `distance_meters`.
- `/market/stats`: новые общие счётчики каталога, подключены к заголовку результатов.
- `/users/me/profile`: получение и изменение профиля клиента.
- `/masters/me/*`: профиль, локации, услуги, рабочие часы, исключения расписания и управление записями мастера.
- `/bookings`, `/bookings/my`, `/bookings/:id`, `/bookings/:id/cancel`: создание, просмотр и отмена собственных записей.
- `/categories`: собственные категории Bookly; не заменяют `/market/categories`.
- `/admin/users` и `/admin/import/runs`: административные маршруты.
- Миграция `00012_frontend_workflows.sql`: `notifications.read_at` и таблица `source_firm_promotions`, связывающая импортированную фирму с мастером и локацией Bookly. На момент проверки маршруты чтения этих связей в HTTP handler ещё не зарегистрированы.

Новые маршруты профилей/записей/администрирования пока не имеют отдельных экранов. Импортированные фирмы и их услуги не являются сущностями Bookly для записи: их UUID нельзя отправлять в `/bookings` как `master_id`/`master_service_id`. Карта использует импортированный каталог; backend в рамках этой задачи не изменялся.
